# Domain docs

Before exploring domain behavior, read the root GLOSSARY.md if present and relevant ADRs in docs/adr/. If a GLOSSARY-MAP.md appears later, follow its relevant context pointers. Proceed when these files do not yet exist; create domain records lazily as terms and decisions become settled.

Use glossary terms consistently. When a proposal conflicts with an ADR, name the conflict and discuss reopening it. Record experiments and evolving alternatives in docs/track/; a hypothesis is not an accepted architecture decision.

This repository has a single context: GLOSSARY.md and docs/adr/ at the root. The existing docs/design/version-catalog.md records earlier catalog research; consult it and docs/track/release-catalog/map.md before catalog work. Treat historical measurements as evidence at their recorded source revision, not current guarantees.
